# AI 周报 · 产品设计文档（MVP）

**版本** v0.1 ｜ **状态** 已确认，待开发

---

## 一、一句话定位

> 周末坐下来跟 AI 聊五分钟，得到一份属于自己这一周的总结，和下周的计划。

---

## 二、要解决的问题

**问题不在「整理」，在「没有东西可整理」。**

目标用户平时不写周报、不做记录。到了周末想复盘，打开一个空白输入框，脑子里一片空白，写两行就关掉，此后再也不打开。

| 常见做法 | 为什么不行 |
|---|---|
| 给一个输入框让他写 | 没有素材，直接卡死 |
| 做一个记录系统让他平时记 | 要改变习惯，成本高，而他本来就不记 |
| 做统计图表 | 没有数据，图表全是空的 |

**结论：不要让他「想起来」，只要让他「回答」。**

回答一个问题，比凭空回忆容易十倍。

---

## 三、核心设计

### 3.1 AI 来采访你，而不是你对着空框写

打开软件，AI 先开口问一个问题；你随口答，AI 顺着追问；问完一块换下一块。你只需要回答，不需要组织语言，也不需要先想好要写什么。

### 3.2 状态机管覆盖，AI 管对话

**这是本产品最重要的一个设计决定。**

如果让 AI 自己决定问什么，它一定会偏——逮着一个话题聊十轮，漏掉一整块内容。

所以两者分工：

- **应用（状态机）**：保证「事情 / 人际 / 状态 / 收尾」几块都被问到
- **AI**：在当前这一块里，怎么问得自然、怎么追问得深

每轮流程：应用告诉 AI「现在在第几块、已经问了几题、用户刚说了什么」→ AI 回一句 `{ message, dimensionComplete }` → 状态机据此决定留在本块还是推进下一块。

追问上限 **2 层**，到顶即换块。

好处：覆盖逻辑是纯函数，**不连 AI 就能完整单测**。

### 3.3 永远能喊停

界面上固定存在一个「聊够了，看结果」按钮。

这是对话式产品最常见的死法：AI 兴致勃勃地问第 15 个问题，用户早就想走了。AI 覆盖完所有维度后，也应主动收尾询问。

### 3.4 刷新不丢

聊了五分钟刷新一下全部消失，会非常恼火。会话过程与最近一次结果都保存在本地。

---

## 四、核心流程

```
打开
 ├→ 设置页（首次）：填 API Key / 接口地址 / 模型名
 └→ 对话页：AI 一问一答采访，可追问，可随时喊停
     └→ 结果页：三张清单 + 本周热点 + 下周计划 → 复制
```

---

## 五、功能范围

### 本版要做

| # | 功能 | 说明 |
|---|---|---|
| 1 | 设置页 | 填 API Key、接口地址、模型名，本地保存 |
| 2 | 对话页 | AI 采访式一问一答，支持追问，可随时结束 |
| 3 | 结果页 | 事 / 人 / 悬着 三张清单、本周热点、下周计划、复制全文 |
| 4 | 本地留存 | 会话中途不丢；关掉再开能看回上次结果 |

### 本版不做

- **物品维度** —— 需求尚未想清楚，不硬塞
- **平时记录功能** —— 与「采访式回忆」重复，且会显著加重产品
- **历史记录列表、周与周对比** —— 先验证单次是否有价值
- **任何统计图表** —— 没有数据支撑，图表只会是空的
- **账号、云同步、分享** —— 个人自用工具，本地优先
- **手机端** —— 先做桌面

## 六、采访脚本（首版）

| 块 | 主问题 | 追问方向 |
|---|---|---|
| 事情 | 这周主要忙了些什么？ | 哪件最花时间？后来结果怎么样？ |
| 事情 | 有没有本来打算做、结果没做成的事？ | 卡在哪一步？ |
| 人际 | 这周跟谁打交道最多？ | 有没有卡在谁那里？ |
| 人际 | 有没有想联系、但一直没联系的？ | 为什么没联系？ |
| 状态 | 这周整体感觉怎么样，累不累？ | 主要是什么造成的？ |
| 收尾 | 还有什么我没问到、但你想说的？ | — |

约 10 轮，用时 5 分钟左右。

## 七、结果页

```
本周清单
  事     · 改了三版方案，还没定
  人     · @老王 — 方案卡在他那儿没拍板
  悬着   · 报销拖了两周没交

本周热点         3~5 条，这周真正值得记住的
下周计划         3 件重点 + 2 个要跟进的人
                                    [ 复制全文 ]
```

结果由第二次 AI 调用生成，以结构化 JSON 返回。

**AI 返回的 JSON 一定会偶尔不合法**，解析层必须带容错与降级，不允许崩溃。

## 八、技术方案

| 层 | 选型 | 说明 |
|---|---|---|
| 外壳 | Electron | 本机已具备 Node 24，无需额外环境；主进程写薄，便于日后更换 |
| 前端 | React + TypeScript + Vite | |
| AI | OpenAI 兼容 `/chat/completions`，SSE 流式 | 兼容 DeepSeek 等，可随时更换模型 |
| 存储 | 本地 JSON 文件 | 配置与最近一次会话分开存放 |
| 测试 | Vitest | 见第十节 |

### 已知取舍

- **包体积约 150MB** —— 个人自用可接受；体积优势只在分发给他人时才值钱
- **API Key 明文存于本机** —— 个人工具可接受，但需知悉
- **不选 Tauri 的原因** —— 本机没有 Rust 工具链，配置成本远超 MVP 阶段的收益

### 为将来更换外壳留的口子

主进程只承担「读写本地文件」与「发起网络请求」，不承载任何业务逻辑；业务逻辑全部放在前端与共享层。这样日后换成 Tauri，前端代码可 100% 复用。

## 九、里程碑

每个里程碑一次 commit，测试全部通过方可交付。

| | 内容 | 交付物 |
|---|---|---|
| M0 | 脚手架：Electron + Vite + React + TS + Vitest | 能打开一个空窗口 |
| M1 | 采访状态机 + 对话 UI + 假 AI | **不接 AI、不花额度即可完整聊完一轮** |
| M2 | 接入真实 AI（流式）+ 设置页 | 与真实模型对话 |
| M3 | 结果生成 + 结果页 + 复制 + 本地留存 | 全流程走通 |
| M4 | 打包为 Windows 可执行文件 | 双击即用 |

**M1 是关键节点**：不接 AI 就能验证交互手感。若此时判定「这个对话很烦」，项目即可止损，代价最小。

---

## 十、测试要求

- **采访状态机**：维度覆盖顺序、追问上限、提前结束、边界情况
- **AI 返回解析**：合法 JSON / 被 markdown 包裹 / 字段缺失 / 完全非法 → 降级不崩
- **Prompt 组装**：上下文拼接正确
- **本地存储**：读写、首次运行无文件、文件损坏
- 提供 mock AI 服务支撑集成测试，**不依赖真实网络**

---

## 十一、待验证的假设与风险

| 假设 | 若不成立怎么办 |
|---|---|
| AI 问的问题问得对 | 调整脚本与 prompt；极端情况退回固定问题清单 |
| 归纳出的清单像自己这一周 | 提高追问深度，或让用户在结果页手动修正（本版不做） |
| 最后那份热点会想看第二遍 | **这是项目的生死线**。若否定，应考虑停做，而非加功能 |
| 一周只用一次但能坚持 | 接受低频。怕的不是用得少，而是每次都很平庸 |
