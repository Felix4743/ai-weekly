## 0.9.10 是什么（当前这一版）

在 0.9.9 上做的仍是一件**纯界面的事**，功能与交互流程一行没动。两笔一起做：**底子从冷灰换成暖纸**
（用户原话「将这个软件进行优化ui界面再好看一点」，方向在四个选项里选了「再往暖走一步」与
「再搬几个会动的小组件」，另外点名要一个黑色主题），以及**补上 0.9.7 说好要做、一直没做的深色主题**。

1. **颜色整组往暖挪半格** —— 底 `#eef1f6` → **`#f6f3ee`**；墨色三档从冷灰换成暖褐
   （`--ink: #101828` → **`#2a2016`**，`--ink-2: #57493a`，`--ink-3: #8a7a68`）；线与次级面板
   换成米色系（`--line: #e5e0d6`、`--panel-2: #fafaf7`、`--panel-3: #f4f2ec`）。白卡片仍是纯白，
   主色青绿只换刻度（`#0d9488` → `#0f9488`）。改的仍然只有 `demo/src/styles.css` 顶部那套令牌。
2. **大标题更大、字距更紧、正文下垫一层纸纹** —— `--fs-display` 30 → **34px**，标题 `letter-spacing`
   收到 `-0.022em`；纸纹是一张 URL-encode 的 SVG `feTurbulence` 噪声（160×160、透明度 0.035），
   当 `body` 背景的最上面一层。远看是「纸」，凑近才看得见颗粒。
3. **深色主题** —— 顶栏最右多一颗太阳 / 月亮按钮。**首次打开跟随系统**（系统设了深色，开出来就是深的），
   手动切过一次就记住（`localStorage['ai-weekly.theme']`）。做法是**先把写死的颜色全部收进令牌**，
   再补一整块 `[data-theme='dark']` **只重写令牌** —— 一条组件规则都没动。深色不是纯黑，是**暖黑**
   （底 `#1b1815`），跟亮色那套暖纸同族；纸纹在深色下透明度是另一个数（0.045），因为黑颗粒在暗底等于没画。
   主题只是界面偏好，**不进配置、不进归档、不进提示词**。
4. **四处会动的小东西**（都是自己写的，没为一个效果引库）—— 页头概览与近三周卡片**入场时轻轻浮上来**
   （`ui/FadeIn.tsx`）；大标题**逐字从模糊里浮出**（`ui/BlurText.tsx`）；总览页「已经记了 N 周」里的
   数字**滚上去**（`ui/CountUp.tsx`，等宽数字，跳的时候整行不抖）；指针划过「本周主线」与「下周计划」
   两张卡时，卡上**跟着指针走一团柔光**（`ui/spotlight.ts`，挂两个事件处理器，不是包一层组件）。
5. **采访页那一遍** —— 气泡圆角 16 → 18px、行高 1.7、边线更淡，指针放上去轻抬一下；输入框容器更厚；
   顶栏那排话题标签的玻璃底色收成令牌。
6. **该静止的地方仍然静止** —— 系统开了「减少动态效果」时，四个动效全部退化成直接出终值
   （数字连第一帧都不滚）；逐字标题对读屏是一份完整的 `sr-only` 原话，动画那层整个 `aria-hidden`。
   **顺带给那排星也留了后路**：`PeekRating` 的颜色本来就由 `--star` / `--star-off` 兜底，
   所以深色下自动跟着走，一处没写死。

**怎么验的**：`npm run typecheck` 干净；`npx vitest run` **39 个文件 / 783 个用例全过**
（0.9.9 收尾时记的是 39 / 808 —— 中间那次「移出一个与本项目无关的本机工具」删掉了磁盘上 42 条用例，
变成 37 / 766，这一版新增 17 条回到 39 / 783）。新增两个用例文件：`demo/src/ui/theme.test.ts` 8 条
（没存过跟随系统 / 存过就只认存的 / 存的值不认识当没存过 / 亮色是**摘掉**属性而不是留个空串 /
localStorage 坏掉也照切不报错）、`demo/src/ui/motion.dom.test.tsx` 9 条（拆字之后读屏仍读到完整原话、
减少动态效果时数字第一眼就是终值、柔光坐标真的写进了 `--spot-x` / `--spot-y`）。
`npm run build` 出 `dist/assets/index-CCuZE2tx.css` 44.68 kB（gzip 8.96）/ `index-B4Ul7brZ.js`
248.10 kB（gzip 90.74）—— 比 0.9.8 的 CSS 36.05 kB 涨了 8.6 kB，主要就是深色那整套令牌与纸纹。
截图：`demo/live-output/ui-0.9.10b2/`（亮色，11 张）与 `ui-0.9.10b-dark/`（深色，10 张）；
柔光跟着指针走，静态截图本来永远拍不到，所以脚本里专门摆好坐标多拍了一张 `result-spotlight.png`
（亮色那份因此比深色多一张）。
**截图脚本还学了一课**：不显式指定主题时它会跟随系统，这台开发机是深色偏好 —— 亮暗两遍会**拍成一模一样**
（两张 `result-top.png` 的 sha256 完全相同），要留亮色证据必须写 `--theme light`。

**这一版没做的**：设置页那一轮、窄窗口下的排版、跟着系统主题实时切换（只在启动时读一次）。

## 0.9.9 是什么（0.9.10 之前那一版）

在 0.9.8 上加了一件新东西：**周中随心记**。周中想到什么就记一句，周末梳理的时候当线索带上。

用户原话是「我还想加一个功能，就是周中随心记，你懂我意思吗？我们先讨论一下」，讨论后定下三条：
**一句话 + 日期自动**（日期取本地当天，不用手填）、**归类自动**（不让用户选类目）、
笔记**存在归档文件里**（`weeks.json` 那一层，`WeekEntry` 多一栏 `notes`，不另开文件）；
而且**先只进采访** —— 笔记自己不会变成结果里的条目，只有真聊到的才由模型写进结果。

1. **第一屏换成一张「随心记」卡**（用户原话：「归档格式我觉得需要改一下，这个第一个界面问题就很大，
   我觉得把上面的四栏和下面的还差一步，还有本周梳理可以删掉，然后补充个随心记。位置还没想好」）——
   这一周的采访还没开过头时，整页只有这一张卡：一行输入 + 回车（或点「记下」）就存下；列表**最新在上**，
   每条是「日期 + 原话 + 自动归类（事情 / 人际 / 物品 / 成长）+ 删掉」；空着的时候写
   「这周还什么都没记。想到一句就写在这儿，别等周末。」；底下一句「开始这周的梳理」才进打分卡。
   原来第一屏上的**四栏标签（事情 / 人际 / 物品与支出 / 成长）**、**「还差一步」那块空卡**、
   **「生成我的本周梳理」按钮**全部撤掉了。
2. **采访里的四栏标签留着**（用户原话：「留着」）—— 现在的作用是随时跳到另一块，还带
   「事情 1/4」这样的进度。
3. **发送框那排小芯片多一颗「记一句」** —— 点开是同一张随心记卡的**紧凑版抽屉**：说明句收起来、
   列表自己滚、底下不再摆开始按钮、右上角换成一个「收起来」的叉。加它的原因是落地页上写着
   「开始之后随时可以回来接着记」，得让这句话是真的。
4. **打分卡与定档这两步下面那块空的对话区（原来标题写着「还差一步」）整个不再画了。**
5. **归类是猜的，猜错不影响什么** —— 窄词表命中就归类，其余一律归「事情」：提到张总 / 妈妈 / 同事
   这类人 → 人际；买、快递、账单这类词 → 物品；早起跑步、看完书这类 → 成长。标签只是回头看着方便，
   **不进提示词、不进结果、不进导出**。
6. **笔记怎么进采访** —— 开场提示词里会带上这一周的笔记（只给「9月28日：原文」，
   **不给模型猜出来的分类**），并交代清楚不要把笔记当清单念一遍 —— 周三记的「要确认预算」，
   周五可能早就谈完了，所以是问「这条现在怎么样了」，而不是拿它当事实复述。
7. **老档照读** —— 存档格式从 0.8.1 用到现在，这一版 `WeekEntry` 多了一栏 `notes`：缺这一栏读出空列表，
   坏笔记逐条丢掉，缺的日期与分类现场补出来；只有随手记、一个字没聊过的一周也留得住；
   重新生成结果、一周里接着补、挪周都不会把笔记弄丢。

**怎么验的**：`npm run typecheck` 干净；`npx vitest run` **39 个文件 / 808 个用例全过**（0.9.8 是 37 / 752）。
新增用例：核心层 `demo/src/core/notes.test.ts` 18 条、`demo/src/core/archive.test.ts` +12 条、
`demo/src/storage/store.test.ts` +6 条、`demo/src/core/prompts.test.ts` +5 条；界面
`demo/src/ui/chatPage.render.test.ts` +6 条，以及新的 jsdom 文件 `demo/src/ui/notesCard.dom.test.tsx` 10 条
（敲字回车真的记下了、空着点不动、只敲空格不算、叉掉那一条、点「开始这周的梳理」进采访、抽屉开合）。
内存：`node scripts/measure-memory.mjs --walk 2` 跑下来 JS 堆整场恒定 **9.54 MB**、DOM 节点 47 → 105，
跟 0.9.4 那次量的一致（这一版没有新增定时器与常驻订阅）。

## 0.9.8 是什么（0.9.9 之前那一版）

在 0.9.7 上换掉了一件东西：**状态那四项打分用的那排星**（提交 `1710923`
`feat(ui): 状态打分换成 PeekRating —— 预览、整排拖动、键盘与气泡`，10 files / +1490 −111，
37 个文件 / **752 个用例全绿**，比 0.9.7 多 11 个；另有 `fea074a` 是截图脚本跟着改）。

用户原话是「这个对话框主要是优化一下ui界面，我在reactbits.dev上找到一些很有趣的ui。
然后我们先把这个打分系统给优化了」，并贴来了 React Bits 的 `<PeekRating />` 源码。
所以这一版**只换那排星的交互与观感**：分数怎么存、结果页写什么、导出写什么**一个字没改**。

1. **换成了什么** —— 新文件 `demo/src/ui/PeekRating.tsx` + `PeekRating.css`，官方源码原样搬进来：
   鼠标**划到第 N 颗，前 N 颗一起亮、一起轻轻抬起来**（指针正下方那颗再放大一点），跟着指针
   有一枚小气泡写着这一档叫什么；**按住可以左右拖着选，松手才真的落分**；再点同一颗（或
   `Backspace` / `Delete`）回到「没打分」；键盘 ←→↑↓ ±1、`Home` / `End`、空格 / 回车选中。
   原来那排是自己写的字符 `★` 按钮：划过去只有那一颗放大一点、**没有任何预览**。
2. **数据口径一点没变** —— 组件只认 0–5，而本项目「没打分」是 `undefined`（0 分与没打分在
   数据上是一回事，都不写这个键）；这层换算收在 `demo/src/ui/StateScore.tsx` 一处，
   **组件里不塞业务规则**。结果页、总览页、导出、归档格式全部照旧。
3. **第一次引 UI 依赖** —— `@hugeicons/react` + `@hugeicons/core-free-icons`（真图标，不是自绘）。
   从 M0 起「不引 UI 依赖」那条老约束**从此只对自绘图标那部分成立**；另外 `jsdom` 进了 devDependencies
   （只跑测试，不进安装包）。
4. **测试环境往前推了一步** —— 原来只有 node 环境的静态渲染断言，验不了「划过去会不会亮」。
   新增 `demo/src/ui/peekRating.dom.test.tsx`（**唯一一个 jsdom 用例文件**）13 个用例真跑指针与键盘。
   顺带学了一课：亮不亮是 `useLayoutEffect` 画的，**静态 HTML 里读不到 `data-lit`**，
   原来那条断言是错的，改成按 `aria-checked` 数「这一排亮了几颗」。
5. **没换的地方** —— 结果页页头概览那排**只读**小星仍是老样式（它是 `<span>`、点不动）。

**怎么验的**：`npx tsc --noEmit` 干净；`npx vitest run` **37 个文件 / 752 个用例全绿**；
`npm run build` 通过（6102 modules，`dist/assets/index-MUJdt8qO.js` 239.50 kB / gzip 87.42 kB，
CSS 36.05 kB）。截图落在 `demo/live-output/ui-0.9.8/`（gitignore），其中

## 0.9.5 是什么（0.9.6 之前那一版）

在 0.9.4 上动了两处，**归档格式还是没动**：

1. **没感觉的题可以跳过**（用户提的第二条：「我有很多问题是没有感觉的，可以加个没有按键」）——
   发送旁边多一个「**这题跳过**」：点一下**不发请求**，直接推进到下一题；对话里不留
   「跳过了」那种痕迹，结果里也不记跳了几题，**跳过的题就像没被问过**。
   下一题由客户端用那句参考问法顶上（不发请求就没有新文本，屏幕上会一直停着上一题、
   点完看着像没反应）。只在「这一题还没聊完」时出现 —— 主问题问完进入自由聊之后没有题可跳。
   跳掉的正好是这一块最后一道时，跟 `[换块]` 一样顺手把下一块打开。
2. **总结界面重排**（用户提的第三条：「还是总结界面，这个得深度优化一下」）——
   原来「本周主线 + 下周计划」排在第 7、8 位，前面压着六张清单卡，而文档里写着
   主线是这项目的生死线。现在顺序是 **本周主线 → 下周计划 → 事情 → 人际 → 物品 →
   未办 → 状态 → 成长**；页头还加了一条「**这周概览**」：只列打过分的四项星星 + 主线首句，
   第一屏就能看到值得看第二遍的那两句。总览页共用同一套正文，所以那边也跟着变。
   **导出 Markdown 的章节顺序没动**（复制全文仍是 清单 → 状态 → 主线 → 计划）。
3. **采访流从「逐条过题」改成「聊到就算」**（用户的原话：「感觉这个问法还是太机械了」，
   具体感受是「它不看我在聊什么，照着自己的清单走」「不该问的题它还是问」）——
   0.9.3 起每块是一张固定题目清单（事情 6 / 人际 4 / 物品 4 / 成长 2 = 16 道），
   按顺序一道一道问，`[换题]` 的语义是「这一题问到了」。**现在每块只声明 12 个要点**
   （事情 4 / 人际 3 / 物品 3 / 成长 2），先聊哪个、聊几轮、往哪儿追全由模型定；
   覆盖只在 `[换块]` 那行报一次（`覆盖:1,3`），客户端收尾对账：**还差着要点就提示你一句
   （「这块还差 1 样没聊到 · 接着补 / 算了」），补不补你定** —— 真模型实测六个块里四个收尾时
   都缺要点，所以「客户端自动补问」那条路被否掉了（它只能念锚点原文，机械感以补丁形式回来）。
   另外加「每块 10 轮」防打转。**追问池整个删掉了**（它的存在正是「追问像从列表里挑」的来源），
   改成一个「往具体里追」的方向。同时**协议反转**：从「不要前缀解释」改成
   **要求先说一句接住对方的话**再往下问，字数上限 160 → 200 —— 原来那条把「接话」掐死了，
   人设再活泛也只剩一层皮。
4. **它开始记得前面几栏聊过什么**（同一次改动里发现的另一个毛病）—— 以前每一栏各给各的
   上下文，切到「人际」时它看不到「事情」里说过的任何一句，连开新栏都不带对话原文，
   于是「刚听你说……」这种过渡只能硬编（实测它说过「你打了个分，我记住了」，
   而那一栏它根本拿不到分数）。现在整场记录都给它、前面几栏**只作背景**；
   实测五栏的开场全都在引前面栏里的原话。另外把「这一块最多 10 轮」也告诉了模型，
   让它自己配速（实测「人际」那栏曾聊满 10 轮被硬收掉）。

代价写在 `docs/技术方案.md` 第八节：块内没有题序之后，「聊完了没有」全靠模型说，
只剩几条上界；模型要是不按格式报覆盖，收尾对账这条链路等于不生效。

这一版没动的东西：三档深度的分钟数与追问上限、状态追问的阈值、一周两次接着补的合并规则、
归档格式、结果八栏与导出章节顺序。

**为什么不留快照文件夹**：一份快照和它对应的 tag 内容完全一样，却多占一份工作区，
翻目录时还要在两份几乎相同的源码里挑，更容易让人误以为这里才是源码。tag 能 checkout、
能 diff、能回滚，也不额外占空间 —— 有 git 就没必要再抄一份。

代价得说清楚：**tag 在 `.git` 里，而 `.git` 和这个工作区在同一块盘上。**

## 万一还要再导一次源码快照

两个坑（都踩过，写下来省下一次）：

```powershell
# ⚠️ 必须显式列出顶层路径，不能直接 git archive <tag>：
#    mvp/ 自己进了版本库，整棵树导出会把 mvp/ 一起塞进去，于是变成
#    mvp/mvp-v0.9/mvp/mvp-v0.5/ 这种套娃。
# ⚠️ 中文文件名必须走 zip；tar 在 Windows 上会把 docs/ 里的中文名解坏（实测踩过）。
git archive --format=zip -o "$env:TEMP\snap.zip" mvp-v0.9 AGENTS.md .gitignore demo docs
Expand-Archive -Path "$env:TEMP\snap.zip" -DestinationPath "$env:TEMP\mvp-v0.9" -Force
```

导到仓库外面去就行（比如别的盘）。要是导回 `mvp/`，还得在 `.gitignore` 里单独放行
（`!mvp/mvp-v0.9/`），再占一份版本库空间 —— 没必要。

## 归档下一份：打个 tag 就够了

```powershell
git tag -a mvp-v0.9 -m "0.9：一句话说清这一版做了什么"
```

tag 是权威版本：能 checkout、能 diff、能回滚。**不再往本目录导源码快照。**
