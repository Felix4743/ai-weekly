## 0.9.4 是什么（当前这一版）

在 0.9.3 上动了两处，**归档格式还是没动**（老周记录照读，`followUp` 是可选字段）：

1. **打完分之后接着问**（用户提的第一个问题：「第一步打完分之后就没后续了……我想打完分之后
   才根据打分情况进行提问」）—— 定档之后多了一步「**状态追问**」：四项里 **≤ 2 星**的那几项
   挨个问「是什么挡着、能不能挪开」（睡眠问「睡不够是什么挡着的」，运动问「是没时间还是没劲，
   时间能不能挤出来」），**四项都还行就整步跳过**，看不到一个空的步骤。聊出来的小结落在结果页
   「状态」那一栏里的第二格，导出写成 `> **追问**：…`。
   代价说清楚：**分数从此给模型看**（0.9.3 时提示词里连 `scores` 这个词都没有），
   不给看就问不出「睡眠 2/5 是为什么」。写死的那条边界没变 —— 分只由界面点出来，模型写不了。
2. **省内存** —— 关掉独立的 GPU 进程、改用低配模式：进程 **4 → 3**，空闲工作集
   **296 → 265 MB**、私有 **202 → 138 MB**（同一台机器实测）。顺手量清楚了「我们自己的代码
   有没有在涨」：JS 堆整场恒定在 **9.54 MB**，DOM 只随当前那一步的消息线性长（切块会掉回去）。
   剩下那 200 多 MB 是 Chromium 的地板，应用层没有可捡的漏。

这一版没动的东西：16 个主问题、三档深度的分钟数与追问上限、八栏结果、归档格式、
一周两次接着补的合并规则。

## 0.9.3 是什么（0.9.4 之前那一版）

在 0.9.2 上动了四处，**归档格式还是没动**（老周记录照读）：

1. **状态改成开场一张打分卡** —— 四项（心情 / 睡眠 / 运动 / 饮食）各一排 0–5 星，点一下就是几分，
   **再点同一颗 = 取消**（数据里不写这个键，等于「没打分」）；下面还有一行备注，想说什么写在那儿。
   原来「挂在每条回答下面」的星取消了：打完卡才开始问这周的事。
   你 0.9.2 之前留下的状态四行文字，读档时会**并成一行备注原话不动**（例：
   `身体：睡眠、运动、吃饭三样都说满足…；情绪：…`），不会丢。
2. **「心智」从状态里拿出来，独立成「成长」放最后** —— 不打分，问的是「这周长了什么见识、想通了什么」；
   结果页给它一张纯文字卡，「复制全文」也多一段。主问题从 18 道减到 16 道（状态那 4 道变成了打分卡）。
3. **提问只给「要问到什么」，措辞交给模型** —— 每道题现在只有一句意图 + 一两个示例，
   提示词里写明「那是意思不是台词，别照抄、别一周又一周用同一句」；换题之前必须先确认这一轮要问到的真答到了。
   逐条对照与理由在 `docs/采访提问-文案改进.md`。
4. **一周里聊第二次默认「接着补」** —— 开场先把这周已经记下的复述一句再问「今天补点什么」，
   生成时**并进同一份记录**（新的在前，旧的不会被顶掉）；想把旧的彻底换掉，在采访页点「从头再聊一遍」。

**0.9.3 不改归档格式**：老周记录读回来只是把状态四行并成一行备注、补一个空的 `growth` 列表；
只有你真点了星、真聊了成长，才会多出那些内容。

## 0.9.2 加了什么（0.9.3 之前那一版）

在 0.9.1 上动了两处，**结构一条都没动**（还是 18 道主问题、三枚协议标记、八栏结果、老归档照读）：

1. **状态四项各一颗 0–5 星** —— 采访里每答完一道状态题，就在**那条回答下面**挂一排星，点第 N 颗就是 N 分；
   **再点同一颗 = 取消**，也就是「没打分」（数据里干脆不写这个键，以后做趋势才不会被当成 0 分）。
   结果页的「状态」四行右侧也能改，改完自动落盘，「复制全文」会带上 `（4 / 5）` 这样的写法。
   **分数只由界面点出来**：模型在提示词里看不到分数，生成与「重新整理」两步都拿界面上的真实点击覆盖它。
2. **全部提问文案重写**（你提的「提问的文案我还需要改进一下」）—— 18 道主问题、五个追问池、三档问法的说法、
   星星旁那句，全部改成口语：一句只问一件事、不写行话、不问「为什么」改问「当时怎么样」；
   顺手修掉提示词里「一次只说一句话、问一到三个小问题」那处自相矛盾。
   逐条「旧 → 新」对照在 `docs/采访提问-文案改进.md`（哪一句你觉得还不如原来，说一声就换回去）。

**0.9.2 不改归档格式**：老周记录读回来 `state.scores` 就是没有（等于「没打分」），不需要迁移；
只有你真点了星，才会多出那四个数字。

## 0.9.1 加了什么（0.9.2 之前那一版）

在 0.8.1 的采访流上加了四件事，**四栏（事情 / 人际 / 物品 / 未办）一条都没动**：

1. **状态先行** —— 开场不问事，先问身体 / 情绪 / 精力 / 心智（四行纯文字，结果页第五张卡）。
   刻意**不打分**：分数与趋势归「以后功能」，类型里留了 `scores?` 的口子。
2. **三档深度** —— 状态聊完弹出三个按钮（深度 20 分钟 / 每题最多追问 5 次、中度 12 / 2、快速 5 / 1），
   由用户点，不由模型判；中途可以改口。
3. **上周对账** —— 上一周有记录才问（把上周的「下周重点 + 要跟进的人」复述给他）；没记录直接跳过。
   没落地的写进「未办」并带上「上周说好的」，做到的不单记，**结果页不新增「对账」一栏**。
4. **结果八栏** —— 在原来七栏基础上多一栏 `state`；老归档（0.8 的 result）读回来时这一栏补四个空串，
   不会因为缺字段整条读不出来。

另外协议从两枚标记变成三枚：`[追问] / [换题] / [换块]`。

## 为什么装的是 0.8.1（0.9.0 退回来了）—— 这段是历史，留着免得再踩

0.9.0 把复盘改成五段（一句话 / 做了什么 / 问题与建议 / 上周对账 / 下周计划），代价是
0.8 的四栏（事情 / 人际 / 物品 / 未办）被压成两栏半 —— **「人际」和「物品」在五段里没有对应位置，
读旧档时明确不迁**（`demo/src/core/legacy.ts`：只并入 `highlights + events`、`pending`、
`nextFocus + nextFollowUps`；`people` / `things` 原地不动，而归档一旦按新格式写盘就再也读不出来）。
用户 2026-10-02 打开后发现「人际、物品」不见了，决定**先退回 0.8.1、这次数据保住**。

0.9.0 没有丢，也没有被删：源码在 tag `mvp-v0.9`（提交 `bc36d66`），安装包在
`demo\release\ai-weekly-0.9.0-setup.exe`。要再装回去，对着它跑一次安装、路径改成
`D:\AI周报`（**不要再装进本目录**）即可（装之前先备份 `%APPDATA%\ai-weekly\`，0.9.0 会按新格式改写归档）。

**为什么不留快照文件夹**：一份快照和它对应的 tag 内容完全一样，却多占一份工作区，
翻目录时还要在两份几乎相同的源码里挑，更容易让人误以为这里才是源码。tag 能 checkout、
能 diff、能回滚，也不额外占空间 —— 有 git 就没必要再抄一份。

代价得说清楚：**tag 在 `.git` 里，而 `.git` 和这个工作区在同一块盘上，仓库也没有远端。**
也就是说整个项目现在只有这一份拷贝。要真正的备份，得把仓库推到远端，或者导出一次
`git bundle` 放到别的盘去。

## 万一还要再导一次源码快照

两个坑（都踩过，写下来省下一次）：

```powershell
# ⚠️ 必须显式列出顶层路径，不能直接 git archive <tag>：
#    mvp/ 自己进了版本库，整棵树导出会把 mvp/ 一起塞进去，于是变成
#    mvp/mvp-v0.9/mvp/mvp-v0.5/ 这种套娃。
# ⚠️ 中文文件名必须走 zip；tar 在 Windows 上会把 docs/ 里的中文名解坏（实测踩过）。
git archive --format=zip -o "$env:TEMP\snap.zip" mvp-v0.9 AGENTS.md .gitignore demo docs
Expand-Archive -Path "$env:TEMP\snap.zip" -DestinationPath "$env:TEMP\mvp-v0.9" -Force
```

导到仓库外面去就行（比如别的盘）。要是导回 `mvp/`，还得在 `.gitignore` 里单独放行
（`!mvp/mvp-v0.9/`），再占一份版本库空间 —— 没必要。
